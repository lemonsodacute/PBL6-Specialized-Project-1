# AI Support structured data lookup

## Root cause and routing

AI Support previously routed free-text messages to `support_knowledge.retrieve()`. Its provider could only select reviewed article IDs; the backend then rendered those articles' instructions. There was no academic-data tool, so a request for an actual student's score could only produce documentation or a knowledge miss.

`support_assistant.provider_answer()` now detects academic requests before any KB/provider call. The supported intents are `STUDENT_SCORE_LOOKUP` and `STUDENT_ATTEMPT_HISTORY`. Accent/case normalization and sentence patterns recognize possessive, subject-first, MSSV, exam/course, and class variants. HOW-TO questions and requests about correcting scores remain on the existing KB/RAG path. Unsupported or incomplete academic requests ask for identification or return a scoped no-match response; they do not ask a language model to invent results.

The new `support_academic` service separates intent extraction, entity resolution, authorization, SQLAlchemy queries, structured results, and Vietnamese response formatting. It does not expose arbitrary SQL or a generic database tool. The formatter uses server-owned templates and trusted fields; academic records never go to Gemini. External provider failure therefore cannot create or alter score claims.

## Permissions and result policy

- Teachers search only students enrolled in their classes, assigned to their exams, or with historical attempts in their exams. Result queries independently require exam ownership, even when a student belongs to a class the teacher manages. Other teachers' results for a shared student remain excluded.
- Students can resolve only themselves. Named/code requests for someone else are denied without a global student lookup. They see only completed, final scores through the existing `student_result_metadata_many()` policy; pending manual grading, in-progress scores, and draft-exam results are not exposed as final grades.
- The current application has no separate persisted score-publication flag. Its answer-key setting is not treated as score publication. No answer keys, individual answers, risk data, or proctoring events are returned by these tools.
- Existing Admin behavior is preserved: admins can resolve escalated support cases, but cannot initiate academic queries through AI Support. Existing student active-exam restrictions also remain in force.
- Both `search_authorized_students()` and `get_student_results()` authorize direct calls. Candidate selections and restored data transcripts are checked again against current permissions. Ownership loss hides previously rendered result text and links.
- Persisted scores come from the existing `saved_attempt()` projection; student final-score visibility reuses the existing metadata helper. The tools do not call report projections that lazily finalize expired attempts, recalculate grading, or commit academic mutations.

## Disambiguation and privacy

Duplicate names produce authorized candidate choices with MSSV where available. The user can select a button, enter a listed number, or supply MSSV. Exam/course and class ambiguity similarly produces choices rather than guessing. Follow-up state retains identifiers and filters, not a copy of a result dataset. That internal state is excluded from the session snapshot.

Search results are capped at eight choices; result responses at twenty attempts, with an explicit truncation message. Candidate queries load only identity fields, class labels are batched, and repeated transcript permission scopes are checked once per snapshot. No student results are inserted into KB documents or escalation article summaries.

The existing audit service records `AI_SUPPORT_DATA_ACCESS`: authenticated actor, intent, tool, target student ID when applicable, outcome/success, and timestamp. Audit metadata excludes names, scores, queries, credentials, and provider payloads. A failed lookup uses a savepoint, returns a retrieval-failure message, and supports retry without falling back to RAG. Existing transcript redaction remains in place.

The UI labels these responses **Dữ liệu hệ thống**. KB replies retain **Tài liệu hỗ trợ**. Appropriate result links are generated by the backend. Data replies do not display troubleshooting feedback controls, and the composer explains that authorized data lookup is supported.
